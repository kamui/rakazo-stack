# Files, settings and environment variables

Where rakazo-stack keeps things, which files you may change, and every setting it reads. Terms are defined in [GLOSSARY.md](../GLOSSARY.md).

## The Instance folder

Everything setup writes goes in `~/rakazo-stack`, on every system. On Windows that's the Linux home inside WSL, not your C: drive. The Instance's data lives in Docker volumes, not here.

```
~/rakazo-stack/                    mode 700
  settings.json                    your choices and recorded versions, no secrets
  secrets.env                      generated passwords and the keys you pasted (mode 600)
  .env                             generated for Docker Compose from the two files above (mode 600)
  rakazo.<tag>.images.yml          Rakazo's own compose file for the recorded release, unchanged
  compose.stack.yaml               rakazo-stack's compose layer
  relay/                           build folder for the Lemonade relay
  computer-egress/                 build folder for the bot-computer firewall
  lemonade/                        Mac only: the voice engine, its versions and its models (about 2 GB)
  logs/                            run logs, and the files `rakazo-stack logs` writes; lemond.log on a Mac
  .lock                            held by whichever rakazo-stack command is running
  .update-check                    when setup or backup last checked for updates
  .update.env                      only while an Update downloads: the new versions
```

Outside it:

| Path | What it is |
|---|---|
| `~/.local/bin/rakazo-stack` | The program |
| `~/rakazo-stack-backups/` | Backups (mode 700), unless you give `backup --output` |
| `~/Library/LaunchAgents/com.github.kamui.rakazo-stack.lemond.plist` | Mac only: the background item that runs voice (mode 600) |

Docker keeps the data in volumes named `rakazo-stack_<name>`: Rakazo's `pgdata`, `appdata` and `webassets`, and, when they're used, `lemonade-models`, `lemonade-llama`, `lemonade-data`, `lemonade-config`, `hindsight-pgdata` and `tailscale-state`.

## Logs

Each run of `setup`, `update`, `backup` and `restore` writes a run log in `~/rakazo-stack/logs/`, named for the command and the time it started in UTC, such as `setup-20261127T120101Z.log`. It starts with the command, the program's version, your system's version, Docker's version and the start time. Each line has its UTC time, and each command the program ran is there with its exit status and what it printed. The newest 20 of each command are kept.

Secrets and personal values are replaced in every log: each value in `secrets.env` by its name, such as `<OPENROUTER_API_KEY>`, and a key you paste, the Owner password and the Backup passphrase as soon as the program has them; your Owner email by `<Owner email>`, the Instance URL by `<Instance URL>`, Tailscale names by `<ts.net name>` and `<Tailscale device name>`, Tailscale addresses by `<Tailscale IP>`, and your home folder by `~`. A Tailscale device name of `rakazo`, the default, stays.

`rakazo-stack logs` writes `rakazo-stack-logs-<UTC time>.txt` in the same folder: see [the guide](guide.md#logs-for-a-bug-report). On a Mac, `lemond.log` is the voice engine's own log.

## Don't edit the generated files

Setup rewrites `.env`, both compose files, `relay/` and `computer-egress/` on every run, so changes you make there are lost. `.env` starts with this line to remind you:

```
# Generated by rakazo-stack setup. Edits are overwritten; run `rakazo-stack setup` to change settings.
```

To change a setting, run `rakazo-stack setup` again. Only these hand edits are expected:

- In `settings.json`, add, change or remove `rakazo_model` and `memory_model`, then run setup. A model name holds only ASCII letters, digits and `~ - _ . / : @`. Setup keeps your values when it rewrites the file, but drops any field it doesn't know.
- In `secrets.env`, delete the `COMPOSIO_API_KEY` line to turn integrations off, then run setup. Never change a generated secret: `ENCRYPTION_KEY` in particular must never change once Rakazo has started, or Rakazo can't read its own data.

## Who can read your secrets

`secrets.env` and `.env` are protected only by file permissions (mode 600), with no keychain. Your own account can read them, and so can anyone in the `docker` group, because that group can start a container that reads any file on the computer. On Linux, the `docker` group is as powerful as `root`. Keep both in mind before adding someone to it.

## `settings.json`

JSON, rewritten by setup on every run. A field that is absent has its default. An example, from an Instance with OpenRouter, memory and Tailscale on:

```json
{
  "schema": 1,
  "program_version": "0.1.0",
  "owner_email": "owner@example.com",
  "model_provider": "openrouter",
  "memory": "on",
  "filled_by_setup": ["owner", "voice", "memory"],
  "access": "tailscale",
  "tailscale_device_name": "rakazo",
  "tailscale_dns_name": "rakazo.example.ts.net",
  "components": {
    "rakazo": {
      "version": "v0.16.0",
      "images": { "app": "sha256:…", "computer": "sha256:…" }
    },
    "tailscale": { "version": "v1.104.7", "digest": "sha256:…" },
    "lemonade": { "version": "v2026.48.3", "digest": "sha256:…" },
    "hindsight": {
      "version": "1.3.0",
      "images": { "hindsight": "sha256:…", "hindsight-db": "sha256:…" }
    }
  }
}
```

Every field:

| Field | Values | Meaning |
|---|---|---|
| `schema` | `1` | The file's format. |
| `program_version` | for example `"0.1.0"` | The rakazo-stack version that last wrote the file. |
| `owner_email` | an email address | The Owner account in Rakazo. |
| `model_provider` | `"openrouter"`, `"openai"`, `"gemini"`, `"anthropic"` or `"none"` | Your answer to the Model provider question. Kept even while the key is blank. |
| `rakazo_model` | a model name | Optional: the model Rakazo's chat uses instead of the default. With OpenAI or Gemini it applies when setup connects the Owner's account to the provider; after that, change the model in Rakazo. |
| `memory` | `"on"` or `"off"` | Your answer to the memory question. Memory runs only when it's `on` and a key is set. |
| `memory_model` | a model name | Optional: the model memory uses instead of the default. |
| `filled_by_setup` | a list of `"owner"`, `"voice"`, `"memory"`, `"model_connection"` | What setup has set up in Rakazo's database: the Owner account, the Owner's voice, the first Space's memory, the Owner's OpenAI or Gemini connection. A later run uses it to tell "you removed it in Rakazo" from "never set". |
| `model_connection_due` | `"new_key"` or `"new_provider"` | Present while the Owner's OpenAI or Gemini connection in Rakazo still has to take the saved key. |
| `model_providers_left` | a list of `"openai"`, `"gemini"` | Providers you switched away from while the Owner still has a connection to them in Rakazo; the Checklist says to remove it. |
| `access` | `"localhost"`, `"tailscale"` or `"bring-your-own"` | Your answer to the access question. |
| `tailscale_device_name` | for example `"rakazo"` | The Tailscale device name. |
| `tailscale_dns_name` | for example `"rakazo.example.ts.net"` | The name Tailscale gave the device once it joined. Without it, joining needs an auth key. |
| `bring_your_own_url` | an `https://` address | Your own Instance URL, for `bring-your-own` access. |
| `components` | see below | The version and image digests of each Component the Instance runs. |
| `holds` | for example `{ "lemonade": "v2026.48.3" }` | Each held Component's version. Absent when there are none. |
| `failed_update` | for example `{ "to": { "rakazo": "v0.17.0" }, "on": "2026-11-27" }` | After a rolled-back Update: the versions it tried and the day it failed. The next Update that goes through removes it. |

Switching access mode keeps the other modes' fields, so switching back fills in your old answers.

`components` has one entry per Component:

| Entry | Fields |
|---|---|
| `rakazo` | `version` (a release tag, such as `"v0.16.0"`) and `images`: the `app` and `computer` image digests |
| `lemonade` | `version` (such as `"v2026.48.3"`) and `digest`: the image's digest on Linux and Windows, the downloaded file's SHA-256 on a Mac |
| `hindsight` | `version` (such as `"1.3.0"`, with no `v`) and `images`: the `hindsight` and `hindsight-db` digests. Added the first time memory runs, and kept while memory is off |
| `tailscale` | `version` (such as `"v1.104.7"`) and `digest`. Added the first time Tailscale runs |

The Instance runs each image by the recorded digest, so nothing changes until an Update records new ones.

## `secrets.env`

The source of truth for every secret: setup writes `.env` from it on every run, and a Backup holds it byte for byte. Setup creates each password once and never changes it.

| Name | What it is |
|---|---|
| `POSTGRES_PASSWORD`, `POSTGRES_APP_PASSWORD` | Rakazo's database |
| `BETTER_AUTH_SECRET` | Rakazo's sign-in |
| `ENCRYPTION_KEY` | Rakazo's encryption of your content |
| `SCREEN_PROXY_SECRET`, `SANDBOX_SUPERVISOR_TOKEN` | Rakazo's bot computers and their screens |
| `LEMONADE_API_KEY` | Lemonade, which only the relay talks to |
| `HINDSIGHT_DB_PASSWORD`, `HINDSIGHT_API_TENANT_API_KEY` | Memory's database, and memory's key, which you paste into Rakazo to connect memory in another Space |
| `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` or `ANTHROPIC_API_KEY` | The chosen Model provider's key. Only that provider's line is kept |
| `COMPOSIO_API_KEY` | The Composio key, when integrations are on |
| `TS_AUTHKEY` | The Tailscale auth key, only until the device has joined |

## Environment variables

`rakazo-stack` reads these. The program removes every `RAKAZO_STACK_*` variable from the Docker commands it runs.

**Setup without questions** (`setup --no-questions`; also read by the setup that `restore` and `update` run):

| Variable | Answer |
|---|---|
| `RAKAZO_STACK_OWNER_EMAIL` | The Owner's email |
| `RAKAZO_STACK_OWNER_PASSWORD` | The Owner's password, needed only when something in Rakazo has to be set up |
| `RAKAZO_STACK_MODEL_PROVIDER` | `openrouter`, `openai`, `gemini`, `anthropic` or `none` |
| `RAKAZO_STACK_OPENROUTER_API_KEY`, `RAKAZO_STACK_OPENAI_API_KEY`, `RAKAZO_STACK_GEMINI_API_KEY`, `RAKAZO_STACK_ANTHROPIC_API_KEY` | The Model provider's key. Only the chosen provider's variable is read |
| `RAKAZO_STACK_COMPOSIO_API_KEY` | The Composio project API key |
| `RAKAZO_STACK_MEMORY` | `on` or `off` |
| `RAKAZO_STACK_ACCESS` | `localhost`, `tailscale` or `bring-your-own` |
| `RAKAZO_STACK_TAILSCALE_DEVICE_NAME` | The Tailscale device name |
| `RAKAZO_STACK_TS_AUTHKEY` | The Tailscale auth key; also read by `restore` when the Instance joins as a new device |
| `RAKAZO_STACK_INSTANCE_URL` | Your own Instance URL, only with `bring-your-own` access |

**Other commands:**

| Variable | Read by | Meaning |
|---|---|---|
| `RAKAZO_STACK_BACKUP_PASSPHRASE` | `backup`, `restore`, `update` | The Backup passphrase, instead of typing it. Empty counts as unset |
| `RAKAZO_STACK_OLD_MACHINE_OFF` | `restore` | `yes` or `no`: the answer to "Is the machine this Backup came from switched off for good?" |
| `RAKAZO_STACK_NO_UPDATE_CHECK` | `setup`, `backup` | `1` turns off the daily check for updates |
| `GITHUB_TOKEN`, or else `GH_TOKEN` | every command | A GitHub token, sent only to `api.github.com`, for when GitHub's limit of 60 requests an hour gets in the way |

When you run `docker compose` yourself, Compose takes a variable from your shell over the same name in `.env`, so don't set names such as `COMPOSE_FILE`, `COMPOSE_PROJECT_NAME` or `COMPOSE_PROFILES` in the shell you run it from.
