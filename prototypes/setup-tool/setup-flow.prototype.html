rakazo-stack setup: how it behaves PROTOTYPE, throwaway

Question: what form should the setup tool take, and does this model of first runs and re-runs feel right? Proposed form: one command, rakazo-stack setup, that is both an interactive wizard and safe to re-run. It asks only what it must, pre-fills everything it can read from the existing Instance, keeps API keys without showing them, never regenerates internal secrets, and writes two files: a settings file (your choices, safe to read) and a secrets file (generated secrets and keys, private). Settings Rakazo keeps only in its database (Owner, the Owner's voice, memory for the default Space) are filled in only when missing; anything you changed in Rakazo's UI is left alone. Every run ends with a checklist of what is left to do by hand.

Nothing here touches a real machine: the "machine", the "Instance" and Tailscale are simulated in memory.
